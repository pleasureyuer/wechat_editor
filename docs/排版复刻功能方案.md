# 排版复刻功能 · 技术方案

> 版本 v1.0 ｜ 2026-07-23 ｜ 目标项目：wechat_editor（Vue3 + Express + SQLite）
> 一句话定位：输入公众号文章链接 → 提取排版 DNA → 存为模板（接入现有主题色/样式预设系统）→ 生成配套 AI 提示词。

---

## 1. 为什么可行（技术前提）

1. **公众号文章页是公开可抓的**：`mp.weixin.qq.com/s/xxx` 无需登录即可 GET（需带正常 UA，注意频控）。
2. **正文全在 `#js_content` 里，且样式天然全内联**：微信保存文章时已把所有样式拍平成 `style="..."`，没有 class 反查问题——这让"解析样式"变成纯 DOM+style 遍历，难度大幅降低。
3. 图片在 `data-src`（懒加载），域名 `mmbiz.qpic.cn`。
4. 项目现有的 **主题色系统 + 样式预设系统（editor.js: createStylePreset / setThemeColor / appearance）** 正好是复刻结果的落点，无需重构。

## 2. 整体流水线

```
输入 URL
  → [后端] 抓取 HTML（UA伪装 + 5s超时 + 域名白名单校验）
  → [后端] 提取 #js_content + 标题/作者/封面
  → [后端] 样式 DNA 解析器（核心）
       ├─ 颜色体系：遍历所有 style 的 color/background/border-color
       │   → 颜色直方图 → 排除黑白灰 → 聚类出 主色/强调色/正文色
       ├─ 组件识别：按启发式规则给每个块打标签
       │   ├─ 标题：font-size ≥ 17px 或 font-weight:bold 的短文本 section/h*
       │   ├─ 引用：blockquote 或 border-left + 背景色的 section
       │   ├─ 卡片：background + padding + border-radius 的容器 section
       │   ├─ 分割线：hr 或 高度小/border-top 的空 section
       │   ├─ 强调：正文内 span 带 color/背景/加粗
       │   └─ 列表 / 代码块 / 表格
       ├─ 版式参数：正文 p 的 font-size/line-height/margin/letter-spacing/text-align 取众数
       └─ 结构骨架：标题层级节奏、段落平均长度、图文比例、
           开头（引导语/图）、结尾（引导关注/二维码）
  → 产出 styleDNA JSON
  → [前端] 复刻预览面板（并排：原文截图区 vs 本编辑器渲染区）
  → 用户确认后双落点保存：
       ├─ 4a 模板：themeColor + stylePresetMap + appearance → createStylePreset()
       └─ 4b AI 提示词：styleDNA + 结构骨架 → Prompt 模板引擎 → 一键复制
```

## 3. styleDNA 数据结构（核心契约）

```json
{
  "meta": { "sourceUrl": "", "title": "", "author": "", "fetchedAt": "" },
  "colors": {
    "primary": "#07C160",
    "accent": "#FF6B35",
    "body": "#3F3F3F",
    "background": "#FFFFFF"
  },
  "typography": {
    "fontSize": 15, "lineHeight": 1.75, "paraMargin": 16,
    "letterSpacing": 0.5, "textAlign": "justify", "textIndent": 0
  },
  "components": {
    "h1": { "matched": "leftLineTitle", "confidence": 0.82, "rawStyle": "font-size:20px;border-left:4px solid #07C160;..." },
    "h2": { "matched": "pillTitle", "confidence": 0.64, "rawStyle": "..." },
    "quote": { "matched": "quoteBlock", "confidence": 0.9, "rawStyle": "..." },
    "card": { "matched": "cardBox", "confidence": 0.71, "rawStyle": "..." },
    "divider": { "matched": "dividerSolid", "confidence": 0.95, "rawStyle": "..." },
    "emphasis": { "matched": "default", "confidence": 0.5, "rawStyle": "..." }
  },
  "skeleton": {
    "headingRhythm": "每 3-4 段一个 H2，H3 少量",
    "paraAvgChars": 85,
    "imageRatio": "每 500 字 1 图",
    "opening": "金句引用 + 首图",
    "ending": "总结卡片 + 引导关注",
    "emphasisDensity": "每段 0-1 处加粗，关键数字用主题色"
  },
  "imageSlots": [
    {
      "index": 0,
      "position": "cover",          // cover | inline | fullwidth
      "ratio": 0.562,              // 高/宽，来自微信 img 的 data-ratio（不下载图即得）
      "widthPct": 100,             // 相对正文栏宽：100/75/50...
      "captionHint": "首图/封面",
      "_sourceRef": "仅分析阶段对照用，绝不持久化（版权红线）"
    },
    { "index": 1, "position": "inline", "ratio": 1.0, "widthPct": 75, "captionHint": "段落配图" }
  ],
  "note": "复刻只记录图片的『位置+长宽比+相对大小』，原图内容不保存、不下载复用"
}
```

## 4. 组件匹配策略（两级降级）

**L1 · 最近邻匹配（MVP 主路径）**：把解析出的组件 rawStyle 与现有 20+ 组件库逐一算相似度（特征：是否有左边框/背景/圆角/居中/边框位置/字号档位），取最高分写入 `matched`。颜色差异不扣分——因为颜色交给主题色系统统一换肤。**结果 = 现有组件 × 提取的主题色**，立即可用、渲染必然兼容微信。

**L2 · 原样式片段兜底（迭代项）**：当 confidence < 0.5 时，把 rawStyle 清洗后存为"自定义组件样式"（需在组件库里增加 custom 类型渲染通道）。首版可先不做，UI 上标注"该组件近似匹配"。

> 经验预警：秀米/135 编辑器排出来的文章嵌套 section 极深（10+ 层装饰），解析器必须做"装饰层折叠"——只取有视觉意义的样式（边框/背景/间距），忽略纯包装层，否则匹配会被噪声淹没。

## 4b. 图片槽位与替换闭环（手机端重点）

这是"不搬运图片"的最佳折中：**复刻图片的「位置 + 长宽比 + 相对大小」，不碰原图内容**，用户再用自己的图填进去。

**提取阶段（后端，零下载）**
- 遍历 `#js_content` 的 `<img>`，读 `data-ratio`（高/宽）与 `data-w`；无此属性时回退到 `width/height` 或父容器占比
- 记录 `position`（封面/内文/通栏）、`widthPct`（相对正文栏宽）、`index`（文档内顺序）
- 原图 URL **仅用于分析时对照，绝不写入 styleDNA / 不落库**

**编辑阶段（前端，占位框）**
- 渲染 `<div class="img-slot" style="aspect-ratio: {1/ratio}; width:{widthPct}%">` 灰色占位，标注「约 {比例} · 点击替换」
- 占位框随主题色微调边框，保持与模板视觉统一

**替换阶段（手机/PC 统一）**
- 手机端：调 `wx.chooseImage`（小程序 web-view）/ `<input type="file" accept="image/*">` 打开相册
- PC 端：`<input type="file">` 选本地图
- 选图后仅本地预览（dataURL），**不立即上传**，保留"重选/还原占位"能力

**推送阶段（复用现有素材通道）**
- 用户点"推送公众号"时，后端逐张把本地图上传到微信素材库 → 拿回 `mmbiz.qpic.cn` 地址 → 替换占位框 `src`
- 与现有 MD 编辑器的图片推送逻辑完全复用，无需新建通道

> 价值：图片槽位让"结构骨架"从文字描述变成可落地的版式约束；同时 AI 提示词里引用这些槽位后，AI 能在重组 MD 时精准预留出"第 3 段后放一张 16:9 配图"的位置，人和 AI 分工：AI 管结构、编辑器管视觉、用户管素材。

## 5. AI 提示词生成（4b）

提示词 = 固定骨架 + styleDNA 填空，产物是给任意 AI（含本工具未来内置 AI）用的**结构重组指令**，让用户的 MD 在"内容结构"上贴合模板，再由编辑器负责"视觉样式"：

```
你是公众号排版编辑。请在不改变原意的前提下，把我提供的 Markdown 重组为
适配以下排版模板的结构：

【标题节奏】{skeleton.headingRhythm}；标题文案控制在 {N} 字内
【段落】每段不超过 {paraAvgChars×1.5} 字，长段拆分；口语化短句
【强调】{skeleton.emphasisDensity}；重要结论单独成段并用 > 引用块
【卡片】把"步骤/清单/注意事项"类内容改写为无序列表（将渲染为卡片）
【开头】{skeleton.opening}，补一句 50 字内的引导语
【结尾】{skeleton.ending}，补一段总结 + 引导关注文案
【配图】严格按以下图片槽位插入占位图（保留比例，内容由用户自替换）：
  - 槽位0：位置={imageSlots[0].position}，比例≈{1/ratio}（即约 {比例描述}），相对栏宽 {widthPct}%
  - 槽位1：位置={imageSlots[1].position}...
  占位写法：![配图建议：{captionHint}，请替换为你的图]()
输出：纯 Markdown，不要解释。

--- 以下是原文 ---
{用户文档}
```

前端交互：模板详情页两个按钮——「应用此模板」（切换主题色+样式预设）和「复制 AI 提示词」。

## 6. 落地改动清单

### 后端（Express，backend/src/index.js）
| 接口 | 说明 |
|---|---|
| POST /api/style-clone/parse | { url } → 抓取+解析 → styleDNA JSON |
| POST /api/style-clone/save | styleDNA → SQLite 持久化（模板从 localStorage 升级到服务端，跨设备） |
| GET /api/style-clone/templates | 我的复刻模板列表 |

新增模块：`fetcher.js`（抓取+频控+域名白名单）、`dna-parser.js`（cheerio 遍历 #js_content）、`matcher.js`（组件最近邻）、`prompt-gen.js`（提示词模板引擎）。依赖仅需 `cheerio`（已有 Node 环境）。

### 前端（Vue3）
- 新组件 `StyleCloneDialog.vue`：输入 URL → loading → 解析结果预览（颜色条 + 组件匹配表 + 置信度 + **图片槽位列表（带比例缩略框）**）→ 确认保存
- 编辑器新增 `ImageSlotPlaceholder.vue`：按 `ratio` 用 CSS `aspect-ratio` 撑开灰色占位框，标注「{比例} · 点击替换」；
  - 手机端：`wx.chooseImage`（JSSDK / 小程序 web-view）/ `<input type="file" accept="image/*">` 调起相册选图
  - PC 端：`<input type="file">` 选本地图；选图后本地预览（dataURL），**不立即上传**
  - 推送公众号时：逐张上传到微信素材库 → 拿回 `mmbiz.qpic.cn` 地址 → 替换占位框的 src
- `editor.js` store：`cloneStyleFromUrl()`、`saveClonedPreset()`（内部复用现有 `createStylePreset` + 主题色自定义）
- 模板列表区增加"复刻模板"分组，带来源文章标题

### 排期（里程碑）
| 里程碑 | 内容 | 验收 |
|---|---|---|
| C1 | 抓取 + DNA 解析器（纯后端，CLI 可测） | 喂 5 篇不同风格文章，输出合理 styleDNA |
| C2 | 组件最近邻匹配 + 主题色落点 | 复刻结果在编辑器渲染 ≈ 原文观感 |
| C3 | 前端对话框 + 保存/应用闭环 | URL → 30 秒内可用新模板 |
| C4 | AI 提示词生成 + 复制 | 提示词喂给 AI 后 MD 结构明显贴合模板 |
| C5 | 兜底与打磨 | 秀米深嵌套文章、SVG 文章降级提示 |

## 7. 风险与边界

| 风险 | 应对 |
|---|---|
| 微信频控/封 IP | 后端限流（每用户每分钟 2 次）、缓存同 URL 结果 24h |
| 深嵌套装饰解析失败 | 装饰层折叠算法 + confidence 低时明示"近似匹配" |
| SVG 交互文章 | 检测到大量 svg 直接提示"暂不支持该类文章" |
| 素材版权 | **只复刻图片的「位置+长宽比」，原图内容不保存不下载**；编辑器中以按比例占位框呈现，由用户从自己手机/相册选图替换——全程不触碰原图版权 |
| 删文/付费文章 | 抓取失败给明确错误文案 |

## 8. 与商业化的关系

「排版复刻」是强付费点：免费用户可解析预览，**保存模板/复制 AI 提示词**计入解锁权益（看广告 12h / 会员），与现有变现体系无缝衔接。
